NSC2Switch R167 — UJ MISS ANIMATION AUDIT
Date: 2026-09-29

Problem
-------
On Tobi custom UJ Kamui whiff, gameplay state returns to neutral but the visible Kamui animation continues/loops until another movement/action forces an animation refresh. Repeated looping causes lag.

Hardware proof — clean whiff log (uzuy_log(4).txt)
--------------------------------------------------
At ~140.355 s, immediately before native UJ cleanup:
- custom char 281, side 0
- semantic UJ = 1
- action = 740
- e80 = 1
- bda4 = 1
- e94 = 138

Native cleanup then executes:
- caller return = main+0x798F34
- PlayAction index = 74
- a2 = -1
- pre action = 740
- post action = 74
- ret = 1

After that cleanup there is no further PlayAction before shutdown, while per-frame logic continues reporting action=74. User observes the visible Kamui clip still looping. This proves logical state and visual animation layer diverge.

Repeated signature
------------------
uzuy_log(3).txt first UJ cleanup shows the same miss signature:
- semantic=1
- action=740
- e80=1
- bda4=1
- PlayAction(74,a2=-1), caller main+0x798F34, pre=740 post=74.

A separate UJ cleanup in the same prior run shows e80=0/bda4=0, so R167 deliberately excludes that path.

main+0x766B8C PlayAction forwards W2 into the actor vtable +0xF98 call, so a2 is behaviorally meaningful.

R167 patch
----------
Existing PlayAction trampoline only; no new gameplay trampoline.
Match all:
  custom actor
  semantic UJ active
  index == 74
  original a2 == -1
  pre_action == 740
  caller_off == 0x798F34

  pre_bda4 == 1

Then:

  Orig(actor, index, effective_a2, a3, a4, a5, rate)

Everything else remains byte/behavior identical. One native PlayAction call only.
